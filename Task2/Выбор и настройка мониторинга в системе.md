# Анализ системы компании и C4-диаграммы в контексте планирования мониторинга.

Системы для которых можно добавить мониторинг

- Internet Shop (Vue, TypeScript, Three.js) — клиентский веб-интерфейс.
- Shop API (Spring Boot) — обрабатывает заказы, взаимодействует с 3D-моделями.
- CRM (Vue, TypeScript) — интерфейс для продавцов.
- CRM API (Spring Boot) — бэкенд CRM.
- MES (React, TypeScript) — интерфейс для операторов производства.
- MES API (C#) — распределяет заказы, рассчитывает стоимость.
- Messages Queue (RabbitMQ) — шина сообщений.
- Базы данных: Shop DB и MES DB (PostgreSQL).
- 3d files storage — S3-совместимое хранилище 3D-моделей.

> Мониторинг должен охватывать здоровье, производительность, доступность и целостность данных на всех уровнях.

# Мотивация

Необходимо добавить мониторинг:

- Для сохранения репутации и прибыли компании. В настоящее время компания теряет клиентов из-за того, что заказы не доходят до адресатов.
- Отсутствует возможность оперативно выявлять ошибки, связанные с заказами.
- Компания узнает о таких инцидентах только от клиентов, что негативно сказывается на репутации и ведет к потере доверия с их стороны.
- Разработчики вынуждены тратить значительное время на выявление места возникновения сбоя и причин, по которым заказ не был отправлен в производство.
- Также мониторинг стоит добавить для прогнозирования нагрузки, чтобы вовремя обеспечить работу систем без сбоя.
- При добавлении мониторинга безопасности, мы сможем проанализировать попытки взлома, непровамерное получение доступа к информации компании, утечки данных.
- Нет единой картины системы, есть отдельные сервисы, связи между ними нет, нет понимания, как работает система в целом. В идеале хочется видеть состояние каждого контейнера, отображать потоки данных (например, заказ прошёл в MES?), создать единый дашборд для всех команд (разработка, поддержка, менеджмент).
- Нет метрик ошибок, сколько их бало, как часто, в каком окружении.

После введения мониторинга ожидается:

- Снижение числа жалоб — за счёт прозрачности.
- Ускорение обработки заказов — за счёт выявления узких мест.
- Повышение доверия B2B-партнёров — API будет стабильным.
- Рост производительности операторов — они увидят новые заказы.
- Ускорение релизов — команда будет принимать решения на данных
